Data Object – Scout Reader  vs. Direct Reader
Scout Reader
▪
FOR ALL ENTRIES procedure is used, which means that 
dependent tables can only be processed after the 
selection table has been processed
▪
Selection table may have been processed in same or 
different block →Last export is used
▪
Attention when changing the rules of the selection table; 
if necessary, a new export is required
▪
Two-level processing of selection tables
▪
Table links are represented via INNER JOINs →A table is 
processed with exactly one statement 
▪
Dependent table can be processed independently of the 
status of the selection table
▪
Note: Events of superordinate tables cannot be processed; 
however, free selections and declarative selections will be 
taken into consideration 
SELECT *
  FROM KNA1
  FOR ALL ENTRIES IN <lt_seltab>
  WHERE
    KNA1~KUNNR = <lt_seltab>-KUNNR
SELECT DISTINCT KNA1~MANDT 
KNA1~KUNNR KNA1~ERDAT […] 
FROM KNA1
INNER JOIN knb1 AS knb1
   ON knb1~kunnr = kna1~kunnr

Table Connection – Concatenated (Key) fields
1. Efficient Data Processing: Treat multiple fields as one for faster 
data transformation
2. Simplified Management: Easier filtering, searching, replacing
3. Improved Data Consistency: Keeps related data together
4. Better Analysis: Improves filtering and relationship visibility
5. Handles Complexity: Manages complex structures by reducing 
individual field handling.
Definition:
A single field formed by 
combining multiple fields to act 
as a unique key.
[Field A] + [Field B] + [Field C] 
↓
[Concatenated Key: A|B|C] 
↓
[Used for linking, filtering, 
consistency]
