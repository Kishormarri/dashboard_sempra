01 — What Changes and Why

In SAP ECC, Customers (KNA1/KNB1/KNVV) and Vendors (LFA1/LFB1/LFM1) are completely separate master data objects. In S/4HANA they collapse into a single Business Partner (BUT000) record with role assignments. The CVI (Customer-Vendor Integration) layer keeps ECC tables in sync.

Key constraint KNB1, KNVV, LFB1, LFM1 are retained in S/4HANA and kept in sync by CVI — they are NOT deleted. But BUT000 becomes the master. All new transactions use the BP screen. Old T-codes (XD01, XK01) redirect via CVI.

Bluefield best-practice (SNP recommended for Sempra) Business Partner creation is a built-in SNP out-of-the-box unit in Mission Control. Each customer and vendor record is migrated as a BP automatically. Dual-role records (same company is Customer AND Vendor) require professional-services harmonisation.
03 — SNP CrystalBridge Toolchain for BP Migration

CrystalBridge Analysis (AN)

  • /N/SNP/SC – System scan (extended)
  • /N/SNP/CW_MDA – Master data comparison: find Cust/Vend duplicates across systems
  • /N/SNP/CW_CUST_COMP – Customising comparison
  • /N/SNP/CW_PRESELECTION – Master data preselection per source
  • Enterprise structure analysis: unused company codes, module usage

Transformation Cockpit (TC)

  • /N/SNP/TC – Scenario: Bluefield type
  • Selections: BUKRS, KUNNR, LIFNR, KOKRS
  • Mapping objects: MAP_KUNNR, MAP_LIFNR, MAP_BUKRS, MAP_WAERS
  • Data objects: Customer master, Vendor master, Address (ADRNR last/first)
  • Post-processing: XPRA, XCLA, SDM (BP creation routines)

Mission Control (MC)

  • /N/SNP/MC – Project orchestration
  • Built-in Bluefield unit: BP creation per customer/vendor
  • Variable: TC_SCENARIO drives all TC API calls
  • Automated tickets on mapping errors
  • Dependency chain: Export → Import → BP create → Validate

Validation (DCV)

  • /N/SNP/FKC – Foreign key + domain checks
  • /SNP/FK02_SUMMARY – DCV summary per table
  • CVI_CUST_LINK / CVI_VEND_LINK – every record linked
  • BUPT – BP consistency check (target = 0 errors)
  • Balance comparison: RFBILA00 + /SNP/CW02_VR_API_BALANCE_CMP

04 — CVI Configuration (20-Step Complete Setup)

CVI must be configured before migration runs. Wrong sequence = wrong BP numbers = full data cleanup required.

Configuration order is non-negotiable Number Ranges → BP Groupings → BP Roles → Account Groups → CVI Mapping → Activate Sync. Activating CVI before number ranges are aligned creates BPs with wrong numbers requiring a full data cleanup — there is no partial fix.

  • CONF CVI: Assign customer account groups to BP roles (OBD2 → FLCU)
  • CONF CVI: Assign vendor account groups to BP roles (OBD3 → FLVN)
  • CONF CVI: Number range mapping — external ranges for migrated records (keep ECC numbers)
  • CONF CVI: Field mapping KNA1/LFA1 → BUT000 — validate all critical fields (NAME1, LAND1, STCD1)
  • CONF Assign role /SNP/XX_MIG_BAPI_SAT_700_ALL on S/4HANA target (separately delivered)
  • SNP Create Bluefield scenario in TC; define KUNNR/LIFNR/BUKRS selections

  • SNP Validate mappings (/SNP/TE02_VALIDATE_MAPPINGS) — resolve all gaps
  • SNP Configure address object: export LAST, import FIRST; SEL_ADRNR in global selection
  • TEST Run full mock load into QA — export + import blocks in background via MC
  • TEST Run BUPT (BP Consistency Check) — target: 0 errors for all migrated BPs
  • TEST Run CVI_CUST_LINK + CVI_VEND_LINK — every record has exactly one BP link
  • TEST Post test customer invoice (FB70) — verify A/R hits recon account 140000
