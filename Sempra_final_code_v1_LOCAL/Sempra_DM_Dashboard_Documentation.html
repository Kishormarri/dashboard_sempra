03
The Three Migration Cycles
DM1 / DM2 / DM3 — what each wave covers
📚 Context
Sempra’s SAP migration runs in three progressive waves. Each wave moves a batch of SAP tables from the source system (ES2) to the target system (SQ1). The dashboard tracks each wave independently and shows a cross-cycle comparison on the master screen.
DM1 — Cycle 1
Wave 1
First migration wave. Includes Reference List (Reflist_m1.xlsx) plus Export/Import reconciliation file (DM1_ES2-SQ1 Export-Import.xlsx). Both EXP and IMP data are available — full reconciliation possible.
DM2 — Cycle 2
Wave 2
Second migration wave. Uses DM2 REF.xlsx and EXPORT IMPORT_DM2.xlsx. Same full reconciliation structure as DM1 — all EXP and IMP data present. Tables in this wave tracked separately from DM1.
DM3 — Cycle 3
Wave 3
Third wave — currently in progress. Only the Reference List (ref dm3.xlsx) is available; it carries both export and import rows in a combined format. Dashboard shows amber “Migration In Progress” banner automatically.

Step-by-Step User Guide
How to launch and use the dashboard — no technical knowledge required
📌 Prerequisites
Ensure data files are in the correct folders on the laptop: C:\Users\KishorMarri\.bob\DM1\, DM2\, and DM3\.
Python 3.8+ must be installed. Run once: pip install flask flask-cors openpyxl pandas xlrd
1
Launch the Dashboard
Open PowerShell in the project folder and run:
python launch_dashboard.py

This starts two background services and opens the master dashboard automatically at http://localhost:5003/Sempra_CrossCycle_Summary_MASTER.html
💡 A new PowerShell window opens for the File Bridge — leave it running. The browser opens automatically in ~5 seconds once the bridge confirms it is ready.
2
Run Full 3-Cycle Automation
Click the ⚡ Auto-Sync All Cycles button in the top toolbar. The button animates with a rainbow sweep while running. Three coloured sync circles appear below the toolbar — one per cycle (blue/purple/green) — spinning while reading and showing the match % when each cycle is done.
⏱ The full sync completes in under 10 seconds. All three cycle cards update live with their reconciliation percentages and badge boxes.
3
Read the Results on Screen
Each cycle card shows:
• A large semicircle gauge — the reconciliation match %
• Total tables in scope vs tables fully reconciled
• Mismatched, not-exported, and not-imported counts
• A badge box with green border (healthy) or red border (issues found)

The cross-cycle comparison table below the cards lets you compare DM1, DM2, and DM3 side by side.
4
Switch Views: Business / Technical / Performance
Three tabs at the top of the page switch the dashboard between views:
• Business View — RAG scorecards and insight boxes for leadership
• Technical View — per-table detail with source/target counts and variance
• Performance View — timing metrics, file sizes, cache hit rates
📄 The Business View is the best view for leadership presentations and printed reports.
5
Drill Down to Individual Cycle Dashboards
Click any navigation button at the top (DM1 / DM2 / DM3) to open that cycle’s detailed dashboard. There you can:
• Upload new Excel files via drag-and-drop
• See a searchable per-table breakdown with EXP/IMP record counts and variance
• Download filtered sub-sets (mismatches only, not-exported only, etc.) as CSV or Excel
• View the rainbow reconciliation progress bar
💾 Results are saved in localStorage so they persist across page reloads without re-running the sync.
6
Export Reports & Prints
Use browser Print (Ctrl+P) and choose “Save as PDF” for a leadership-ready document. The dashboard switches to a clean white background with all colours preserved.

For Excel exports with SAP SE16N source counts, use the 📥 Download SE16N Counts button in the Automation panel (Step 4) — produces a colour-coded XLSX with a Summary sheet.

Technical Architecture
How the system works under the hood — for technical reviewers
🔧 Architecture Overview
The system is a three-layer local stack: a static HTML/JS browser layer, a lightweight Python file-serving bridge, and the local file system where Excel data files live. Nothing is sent to any external server — all calculation happens in the browser using SheetJS for Excel parsing.

Data Flow & Deduplication Logic
How records are counted correctly — critical for accuracy
🔍 Why Deduplication Matters
The migration Excel files contain separate rows for each Export and Import operation on every table. Without deduplication, the same table appears multiple times, inflating counts. The dashboard uses a DISTINCT algorithm — equivalent to SQL’s SELECT DISTINCT — to ensure each unique (Type, Table Name, Record Count) combination is counted only once before summing. EXP and IMP rows are processed separately to avoid cross-type errors. This fix was applied to all 6 aggregation points across 4 files.
RECONCILIATION DATA FLOW — STEP BY STEP Step 1: FETCH Browser → GET /file?cycle=DM1&type=ref → bridge returns gzipped .xlsx bytes Browser → GET /file?cycle=DM1&type=exp → bridge returns gzipped .xlsx bytes (ETag check: if unchanged, bridge returns 304 Not Modified — zero re-read) Step 2: PARSE SheetJS.read(arrayBuffer) → XLSX workbook in memory (100% browser-side) sheet_to_json() → array of row objects Step 3: DEDUPLICATE EXP rows: DISTINCT on (Type="EXP", TableName, RecordCount) → deduplicated set → SUM IMP rows: DISTINCT on (Type="IMP", TableName, RecordCount) → deduplicated set → SUM (EXP and IMP processed SEPARATELY — prevents cross-type dedup errors) Step 4: RECONCILE For each table in REF list: Status = GREEN if EXP_count == IMP_count AND src_count == tgt_count Status = AMBER if counts exist but do not match Status = RED if EXP ≠ IMP OR migration not started Status = GREY if no EXP/IMP data found for this table Step 5: AGGREGATE Match % = (fully reconciled tables) / (total tables in REF list) * 100 Step 6: RENDER Update SVG gauge arc, KPI numbers, badge box, sync circles on screen Save summary to localStorage for persistence across page reloads
📊 DM3 Special Case — Combined File
DM3 has no separate EXP/IMP file. The Reference file contains both Export and Import rows in a combined format. The parser handles this automatically by setting impData = expData (both EXP and IMP come from the same parsed data object). The same DISTINCT deduplication logic is applied. This is why DM3 shows an amber “Migration In Progress” banner until a separate EXP/IMP file becomes available for the cycle.

Security & Data Privacy
No cloud, no external calls — data stays on the Sempra laptop at all times
🔒 Security Statement
No Sempra data ever leaves the local machine. All Excel files are read from a local directory, served via a localhost-only Flask server (bound to 127.0.0.1 — not reachable from the network), parsed entirely in the browser using SheetJS, and results are stored only in the browser’s localStorage. There is no cloud API, no telemetry, no external network calls of any kind.
Risk VectorMitigation in Place
Data leaving the machineAll Flask servers bind to 127.0.0.1 only — not accessible from any other machine on the network
External API callsSheetJS loaded from CDN (one-time JS library only, no data sent). Replaceable with a local copy for air-gapped environments in one line
SAP credentialsEntered in-browser only; passed to localhost SAP bridge only; never written to disk; bridge does not log or store credentials
File access controlOnly files matching the config paths are accessible; no directory traversal; wildcard patterns are validated against the allowed base folders
Persistent data storageOnly reconciliation summary numbers stored in localStorage — no raw table data, no SAP credentials, no PII
Network port exposurePorts 5001, 5002, 5003 all bind to 127.0.0.1 (loopback only) — firewall does not need to be opened

Risks & Mitigations
Risk register for leadership review
LOW
SheetJS CDN Unavailability
Mitigation: Download SheetJS locally and change the <script src> to the local path. One-line change in the HTML file. Pre-built local copy can be bundled as standard.
LOW
Python Not Installed on Machine
Mitigation: Python 3.8+ is a standard IT install. Document as a prerequisite. If unavailable, the HTML dashboards can still be opened manually via file:// with reduced functionality (no auto-sync).
LOW
Data File Path Changes
Mitigation: Update DEFAULT_CONFIG in file_watcher_bridge.py, or POST to the /config endpoint from the dashboard Automation panel — no code restart needed.
MEDIUM
Excel Column Structure Changes
Mitigation: Column index constants (COL_TABLE, COL_SRC, COL_TGT, etc.) are defined at the top of each dashboard <script> block. Updating them requires no knowledge of the rest of the code.
MEDIUM
SAP RFC Connection Failure
Mitigation: The SAP bridge tries 3 RFC methods in sequence. If all fail, demo mode produces deterministic simulated counts for testing without a live SAP connection. Real counts not affected if SAP bridge is not used.
LOW
Port Conflicts (5001 / 5002 / 5003)
Mitigation: Port numbers are constants at the top of each Python file and the launcher. Change in one place — all references update automatically.
LOW
Browser Compatibility
Mitigation: Chrome 90+ and Edge 90+ are fully tested and recommended. SheetJS requires ES2017+ support. Firefox and Safari also work but are not the primary test targets for Sempra’s environment.
