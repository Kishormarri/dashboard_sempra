Billing Migration Business Rules

▶ Rule 1: Rate Category must exist before Contract (EVER) load
EMIGALL processes ZRATE_CAT (TE006) before ZCONTRACT (EVER). If a legacy TARIF code maps to a TE006 entry that doesn't exist in SAP, the contract load will fail with error EMIGALL-102 (value not found in domain). Validate TE006 completeness before EVER run.
▶ Rule 2: Open billing history — DFKKOP requires OPBEL uniqueness
When migrating open A/R items (ZFI_OPENITEM → DFKKOP), the legacy OPBEL (document number) must be unique per contract account. Duplicates cause FI-CA posting errors. Use BODS transformation to add a SPARTE prefix (e.g. E-2024-000001) to guarantee uniqueness across utility types.
▶ Rule 3: Billing document history ERDK — do not re-bill
Migrated billing history (ERDK/ERDM) must be loaded with STATUS=H (historical) and FAKTURIERT=X to prevent SAP from re-running the billing engine on these documents. Set these flags in T7XEMI04 (default values) so they apply to every row without source field mapping.
▶ Rule 4: Price validity date gaps cause billing errors
TE400 DATAB/DATBI ranges must be contiguous with no gaps for each PREKEY. If a customer's billing period spans a price gap, SAP billing program FICA_BL01 will terminate with error. Use BODS to check for gaps and set DATBI=99991231 for the latest price record.
▶ Rule 5: Multi-utility customers — separate TARIF per SPARTE
A customer with both Electric and Gas service has ONE BP (BUT000) and ONE CA (FKKVK), but TWO contracts (EVER rows) — one VERTRAG with SPARTE=E and a separate VERTRAG with SPARTE=G. Each EVER row has its own TARIF. Never share a TARIF across divisions — TE006 is division-specific.
▶ Rule 6: TOU rates require EABL interval reads
Contracts with ABLEINH=TOU must have corresponding EABL records with ABLEINH=TOU and hourly/15-min reads. If only monthly reads exist, the TOU billing schema cannot compute on-peak vs off-peak consumption. Either backfill interval data or migrate TOU customers as standard monthly rate.
